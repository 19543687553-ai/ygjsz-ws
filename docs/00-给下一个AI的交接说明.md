## 1. 你是谁，要做什么

你在接手一个 H5 手游「妖怪金手指」的**私服/协议逆向**项目。

上一棒已经完成：抓包 → 解协议 → 用 PHP(HTTP) + Deno(WebSocket) 复刻服务端 → 官方 H5 客户端能登录、进主城、抽卡、进战斗、推图、GM 改数值、后台维护开关。

上一棒**没完成**（也是你现在的首要任务）：

| 优先级 | 问题 | 目前定位 |
|---|---|---|
| P0 | 战场内**不刷怪物** | 波次来自客户端本地配置，`onCreepInfoPPush` 在 tick 0 已被调用；怀疑是房间分配错乱 + 机器人数据缺失导致战场逻辑早退，需要真机/浏览器录制确认 |
| P0 | **队友不升级房门/床、不出战英雄** | `StartGameP` 里 5 个机器人共用同一份英雄列表 → 客户端报 `[TDServer] 上阵英雄失败，此英雄已在阵上，heroCode=50000001`；且机器人初始资源只有 6~15，官方真人房是统一的初始资源 |
| P1 | 队友和玩家**可能在同一房间** | 房间号由客户端 `AdvBattleRoom.initPlayerEnties` 按 `playerId` 排序分配（机器人 1~5、真人 6）；玩家手动点房间会覆盖自己的分配 → 撞房 |
| P1 | GM 面板**看不到物品 ID**、反应延迟、没有存档 | 物品表在 `data/items.json`（1732 条）但没做成界面；GM 回包只回 `clientReward`，客户端要等下一次推送才刷新数值；存档 800ms 合并写盘 |

## 4. 你要遵守的 5 条铁律

1. **改完必须离线验证再上线**。`server.mjs` 用 Node 打桩跑 `tools/test_sgp.mjs`（编码/解码/回包逐项断言），PHP 用 `php -l` + `php -S` 本地站点跑真实 HTTP。
2. **上线分两步**：① push 到 GitHub（Deno 自动部署，等 20~30 秒后 `curl /health` 确认）；② 打包 PHP zip 让用户上传（你无法直连虚拟主机写文件）。
3. **所有回包字段必须和抓包一致**。多余的字段没关系，缺字段一定炸（客户端大量 `e.xxx` 直接取值）。

5. **不要修改用户存档做实验**。线上 `sy_api/state/player.php` 是用户真实进度；验证战斗走只读路径，别随便发 `82/4` 结算（会推关卡）。

## 6. 下一步怎么做（建议顺序）

### 第 1 步：把「不刷怪 / 队友不动」变成可观测问题

不要猜，**先录一局**：

1. 用 Playwright 打开 `https://zx.lytnb.top/`，登录进主城，点「开始挑战」进战场。
2. 注入探针，每 500ms 采样：`BattleModule.Ins._battleList[0]` 的相关字段、场景里敌人节点数、各阵营的 `builds` 等级、`resources`。
3. 同时开日志上报（`/sy_api/log.php?token=...&mode=json`），把 `[TDServer]` 全量日志抓下来。
4. 对照官方抓包（`data/capture/capture-main.json`）里 `90/12 StartGameP` 的 6 个玩家数据，逐字段 diff。

**预期能立刻看到**：机器人英雄 UUID 重复（`我用了和玩家同一份 heroList`）、机器人资源过低、房间 `roomCode` 冲突。

### 第 2 步：修机器人数据（最可能一次解决两个 P0）

`src/deno-ws/server.mjs` 里 `battleStartGameP()` 现在对 5 个机器人调用 `battlePlayerInfo(p, id, mine, ...)`，`mine = heroListOf(p)` —— **5 个机器人拿到了同一份英雄**。
官方抓包（`data/capture/capture-main.json` 解出的 `playerInfos`，或 `/tmp/sgp_players.json` 的历史结论）显示：5 个机器人各有**不同的** 5 个英雄（code 分别是 50000033 / 50000018 / 50000035 / 50000036 / 50000020，uuid 就是 code 字符串，`attr={1:7}`，`fightCap≈135~140`）。
→ 按机器人 id 固定映射到各自的英雄表，`uuid` 用 `String(code)`，别复用真人英雄。

### 第 3 步：修房间分配

`AdvBattleRoom.initPlayerEnties`（客户端 `assets/main/index.b7927.js`，解码偏移见 `03-协议与数据结构.md`）：

```js
t.sort((a,b)=>a.playerId-b.playerId);
isRobot(t.playerId) ? (o.setCampId(r++), o.setReady()) : o.setCampId(n++);
// 非引导图（level>1）：o.setTargetRoomId(c++)  → 机器人 1..5，真人 6
```

真人如果手动点房间底座，会覆盖 `targetRoomId` → 撞房。
两个可选方案：
- **A（推荐）**：`StartGameP` 里给真人 `roomCode` 固定回 `6`（现在是这么做的），并在入口页注入一段 hook，把「点击房间底座」在 `frame<30` 时拦截/改为 6（需要确认客户端在哪一步允许玩家选房）。
- **B**：先只做观测——统计一局里每个 `campId` 最终 `targetRoomId`，确认撞房是否只在玩家手动点之后出现。若玩家不点就不撞房，那这就是「操作引导」而不是服务端 bug。

### 第 4 步：GM 面板补物品 ID 与存档

- 物品表：`sy_api/data/items.json`（1732 条，字段含 `code/name/quality/...`）。做一个 `sy_api/gm.php` 网页后台：搜名字 → 出 code → 一键发物品（调用 `/sy_api/internal.php` 或直接改 `state/player.php`）。
- 也可把物品表做成 GM 面板的下拉框：面板的 `GMCustomCommand` 里 `add_all_beautyBag_item` / `add_all_artifact_item` / `add_all_hero_chip` 都接受 `code`，接上表即可。
- 反应延迟：GM 回包后服务端已经主动推 `13/5`(PlayerInfoP) / `23/9`(HeroInfoP) / `11/12`(AdventureInfoP)，但要等客户端下一帧处理；如果还慢，检查 `5/174` 回包是不是被 `clientReward` 的飞卡动画挡住。
- 没有存档：当前存档是 `sy_api/state/player.php`（首行 `<?php exit; ?>`，JSON 正文），每次改档 800ms 合并写盘（`SAVE_DELAY`）。如果用户觉得「没存档」，大概率是**同账号多端覆盖**或 Deno isolate 重启丢内存 —— 检查 `internal.php` 的写入是否成功（返回 `{ok:1}`）。

### 第 5 步（可选）：把 GM 面板做成真正的网页后台

用户多次问「为什么没有后台」。最省事的做法：`sy_api/admin.php` 里加一个 tab：数据库（金币/钻石/等级/英雄）+ 物品搜索发放 + 维护开关，全部直接读写 `state/player.php`，不依赖 Deno。

## 7. 绝对不要做的事

- ❌ 不要在没有验证的情况下 push `server.mjs`（Deno 会立刻上线，玩家的客户端直接崩）。
- ❌ 不要把 `state/player.php`、`_config.php` 里的 token、SSH 私钥提交到 GitHub。
- ❌ 不要试图在 PHP 虚拟主机上跑 WebSocket（做不到，这就是要 Deno 的原因）。
- ❌ 不要用 `http://` 或 `ws://`（页面是 https，混合内容会被浏览器直接拦掉，表现为「黑屏/卡进度条」）。
- ❌ 不要删除或改写 `game.html` 的 `<base href="...">`，它必须是 `<head>` 第一行。

## 8. 快速定位「客户端某段逻辑」的方法

`assets/main/index.b7927.js` 是 26MB 的单行压缩包，中文是 `\uXXXX` 转义。搜索前先解码：

```bash
node -e '
const fs=require("fs");
const s=fs.readFileSync("/workspace/妖怪金手指_H5前端/assets/main/index.b7927.js","utf8");
fs.writeFileSync("/tmp/main_dec.js", s.replace(/\\u([0-9a-fA-F]{4})/g,(m,h)=>String.fromCharCode(parseInt(h,16))));
'
```

然后用偏移量切片看上下文（文件是单行，`grep -n` 没用，只能算 index）：

```bash
node -e 'const s=require("fs").readFileSync("/tmp/main_dec.js","utf8");
console.log(s.slice(7999600,8003500))'   # 例：本地战场的 onLogicTick / 出怪初始化
```

已知关键偏移（解码后字符下标，±几十字符会有漂移，用关键字重新定位）：

| 关键字 | 大致偏移 | 是什么 |
|---|---|---|
| `onCreepInfoPPush` | 8,006,036 | 波次表注入（`getTemplateInfoCfg()`） |
| `getRoundCfgs` | 8,837,000 | 战斗类型波次配置，null 会抛「当前战斗类型缺乏波次配置」 |
| `阵营` / `选择房间` | 22,395,900 | 战场操作（EOperationType）与房间选择 |
| `setTargetRoomId` | 22,355,000 | 房间分配 |
| `TDServer` | 22,xxx,xxx | 战场 AI 模拟器（机器人操作都在这里生成） |
| `MakeTestOperRResponse` | 搜索关键字 | GM 回包 → 自动弹奖励/结算 |
| `GMCustomCommand` | `assets/gm/index.4ee85.js` | GM 面板 52 条指令实现 |

> 更稳的做法：用关键字定位，别硬编码偏移——每次热更新都会变。
