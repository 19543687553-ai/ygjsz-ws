## A. 抓包壳（Android WebView）

### A1 抓到的只有 SDK 外壳，没有游戏请求
- **现象**：v1 抓包版只录到 `spirit.wbdd2018.com/h5sdk/*` 的请求，游戏数据一条都没有。
- **根因**：游戏本体跑在**跨域 iframe** 里，`shouldInterceptRequest` 只拦了顶层文档。
- **修法**：v2 对**每个** `text/html` 响应都注入脚本（`isForMainFrame` 不再判断），并在 `<head>` 后插入 hook。

### A2 注入脚本拿不到 WebSocket 帧
- **现象**：hook 装上了，但 `ws_msg` 为空。
- **根因**：hook 装在 `DOMContentLoaded` 之后，游戏已经建好 WS。
- **修法**：注入脚本放在 `<head>` 最前面同步执行，劫持 `window.WebSocket`，在 `onmessage` 里把 `ArrayBuffer` 转 base64 推给原生。

### A3 抓包 JSON 结构
```
{v, savedAt, frames:[{url, recs:[...]}]}
recs[].k = http | ws_open | ws_msg | ws_close
ws_msg 二进制帧在 b（base64），文本帧在 s
```
> 注意：抓包里**没有** module 26（抽卡）的帧，也没有 `CreepInfo`（波次不在网络层，在客户端配置里）。

## B. 部署与环境

### B1 `.htaccess` 不生效
- **现象**：`index.php` 不执行，直接显示目录/`index.html`。
- **根因**：虚拟主机没开 `mod_rewrite`，或者上传时丢了隐藏文件。
- **修法**：`.htaccess` 加 `DirectoryIndex index.php index.html`；同时**不依赖 rewrite**——`index.html` 本身就写成入口守卫（XHR 问 `maint.php`），这样即使 rewrite 挂了维护也能拦。

### B2 PHP 站点返回源码而不是执行
- **现象**：`curl /` 返回了一段 PHP 代码文本。
- **根因**：`_common.php` 的注释里写了 `<?php exit; ?>`，PHP 在 `?>` 处结束了，后面的内容被当 HTML 输出。
- **修法**：注释里不要出现 `?>`；写「文件首行是 exit 语句」。

### B3 Deno「入口点未配置」
- **现象**：部署成功但访问 500/提示 entrypoint。
- **修法**：Runtime Configuration → **Dynamic App** + Entrypoint `server.mjs`。

### B4 GitHub 设备授权链接打不开 / SSH 指纹不对
- **修法**：改用 **Deploy Key**（仓库 Settings → Deploy keys，勾 Allow write access），
  推送用 `GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=no -p 443" git push`（443 端口穿透防火墙）。

### B5 commit 报 `Author identity unknown`
- **修法**：`git -c user.name="ygjsz" -c user.email="ygjsz@local" commit -m "..."`（不要改全局 git config）。

### B6 d8 在 Java 25 下 NPE（打 APK 时）
- **修法**：`JAVA_HOME` 切到 JDK 17，再跑 `d8` / `apksigner`。

## C. 客户端黑屏 / 卡进度条

### C1 黑屏三连（三个原因叠加）
1. **`https://https//域名/...`**：`location.origin` + `getProtocolPrefix()` 拼了两次协议 → 服务端只返回 `host`，客户端用 `location.host` 拼。
2. **静态资源全 404**：游戏页是 `zx.lytnb.top/game.html`，但资源相对路径指向 CDN → 加 `<base href="https://menggui-cdnres.bhsg.lintey.com/huawei/web-mobile/">`。
3. **`parsePerloadConfig` 拿回 404 网页**：`remoteConfig` 走 `files.php`，不要指向 CDN。

### C2 `<base>` 写在 `<link>` 后面 → CSS 仍 404
- **修法**：`<base>` 必须是 `<head>` 的**第一行**。

### C3 加了 `<base>` 后 `_h5_platform is not defined`
- **根因**：`<base>` 让 `/h5SB_dalan.js` 的相对路径变成 CDN 路径 → 404。
- **修法**：不要引外部 SDK，直接在页面里内联一个 SDK 桩（`window._h5_platform = {...}`）。

### C4 卡在进度条
- **根因**：`config.hunfu147127.bin`（4MB）和 `preload_config`（39KB）取不到，或者取到的是 404 的 HTML。
- **修法**：`sy_api/files.php` 直接 `readfile` 输出二进制 + `Content-Type: application/octet-stream`。

### C5 Deno 代理 CDN 极慢 / 15 秒超时
- **根因**：Deno 免费额度 + 跨洋拉 4MB 资源。
- **修法**：**浏览器直连官方 CDN**（它带 CORS），Deno 只管 WS 和 `remoteConfig`。

## D. 协议编解码（最深的坑都在这里）

### D1 封包格式
```
C2S : uint16 total | uint8 module | uint16 cmd | uint8 ssid | body      (头 6 字节)
S2C : uint16 total | uint8 ssid | uint8 id | uint8 count | uint8 module | uint16 cmd | uint8 compress | body   (头 9 字节)
total 含自身 2 字节（抓包里 total = 长度 - 2 或 = 长度，视实现而定，本项目按 buf[0]<<8|buf[1] 表示 body 起点）
```

### D2 `Map<uint32,uint32>` 被编成字符串
- **现象**：解码出 `{"\u0012\n":48,...}`，客户端解析报「协议解析发生错误」。
- **根因 1**：`readMapEntry` 把 key 当字符串解。
- **修法 1**：key 只能按 wire type 判断（0=varint，2=string）。
- **根因 2**：`encode()` 里 `const md = (mapDefs||{})[name+"."+f.name]; encodeField(w, f, v, md || {});` 把字段的 `type` 丢了，于是 Map 的 value 一律按 string 编。
- **修法 2**：`const md = Object.assign({}, f, (mapDefs||{})[name+"."+f.name]||{});`

> 这个 bug 导致 `StartGameP` 重编码后从 19956B 涨到 22654B（战场直接不渲染）。修完 19961B，只差 5B。
> **教训：判断「编码对不对」的标准不是「能编码」，而是「和抓包 raw 的长度、逐字节一致」。**

### D3 `Do not know how to serialize a BigInt`
- **根因**：int64 解码成 BigInt，`JSON.stringify` 直接炸。
- **修法**：`deepClone` 用结构化克隆或 `JSON.stringify(o, (k,v)=> typeof v==="bigint"? String(v): v)`。

### D4 抓包 raw 里 S2C 头 9 字节
`4dfb0001015a000c00` = total 0x4dfb、ssid 0、id 1、count 1、module 0x5a(90)、cmd 0x000c(12)、compress 0。解包时从 `body = buf.subarray(9)` 开始。

### D5 真实回包复用
`data/replay.json` 有 `pairs`（请求 → 真实回包 base64/len）和 `pushes`（真实推送列表）。
当某条指令不知道怎么回时，**先查 replay**，能直接原样回。

## E. 游戏功能

### E1 进主城后「什么都点不动」
- **根因**：早期兜底脚本把所有名字带 `reward` 的弹窗 `active=false`（包括抽卡结果窗），还 `destroy` 了节点 → 后续 `null.showHangUpReward` 崩。
- **修法**：兜底脚本**只允许**隐藏 `hangupoffline` 一个容器，其余一律不动；隐藏用 `active=false`，**禁止 destroy**。

### E2 离线收益弹窗关不掉 / 反复弹
- **根因**：`checkHangupOfflineReward` 用 `getNewAdvHangupRewardDt()`（= `_newAdvInfo.getDt`）判断 `now - getDt >= 7200`；我们早期把 `getDt` 填成了账号创建时间 → 必然超过 2 小时。
- **修法**：`adventureInfo()` 里 `getDt: now()`；`11/13 GetHangUpShowRewardsR` 回空奖励时也要带 `info:{...adventureInfo, hangUpTime:0}`。

### E3 抽卡没反应
- **根因**：
  1. 兜底脚本把结果窗关了（见 E1）。
  2. `GetSearchSummonInfoR` 只回 `{err:0}`，缺 `freeSummon/extractInfo` → 客户端 `undefined` 比较失败，不发请求。
  3. `GetSummonRewardR` 缺 `fakeReward` → 结果窗 `_spawnIcon` 里 `this._data.fakeReward.entites` 抛 `Cannot read properties of null`。
- **修法**：三个全补（`freeSummon:[]`、`extractInfo:[]`、`fakeReward:got`）。

### E4 进不了对局（点挑战没反应 / 卡住）
- **根因 1**：`82/1` 的 `addr` 指向游戏服自己，`authCode="dev_auth"` 是假值 → 战斗服连不上。
- **修法**：`addr = host + "/ws?role=battle&auth=...&bt=...&lv=..."`，同一个 Deno 进程用 `?role=battle` 分流。
- **根因 2**：`90/12 StartGameP` 的 `builds` 里 `attr` 被编成字符串（见 D2）→ 客户端「协议解析发生错误」→ 战场白屏。
- **根因 3**：`StartGameP` 的 `level` 映射 `AdventuretdLevelLO.get(10*level).battleGroundCode`，`BattleGroundLO.get(code)` 为 null 时客户端直接 `throw new Error("战场配置找不到")` → `level` 不能乱填。

### E5 战场渲染了但没内容 / 打完不结算
- `82/4 QuitRoom` 必须回 `{err:0, result:1, uuid:"<战斗uuid>"}`。
  - `err != 0` → 客户端 `_handleQuitRoomRData` 判负 + 弹错误码。
  - 缺 `uuid` → `_finishQuitSettlement(undefined)`，不发 `13/47 VerifyArrival`，进度不落地。
- `82/6 UnfinishedRoom` 必须回 `{err:0, battleType:0}`，否则客户端会自动发「放弃」把对局清掉。

### E6 打完一关弹引导 → 报 `Cannot read properties of undefined (reading 'play')`
- **根因**：`GuideView` 的 `roleSpineHandler` 没初始化好，引导又指不到目标（宽高 0），弹窗吃掉全屏点击。
- **修法**：`get_versionInfoApi.php` 的 `checkConfig` 加 `CloseGuide:1`、`GuideAutoReady:1`（客户端 `switchGuideEnable(!v)`）。

> 这是「打完一关就卡死、什么也点不了」的**真正原因**，比服务端问题更隐蔽。

### E7 「没有队友不能下一关」
- **根因**：`90/12 StartGameP` 只下发 1 个玩家 → 战场 6 个阵营只有 1 个有数据。
- **修法（已做，但仍有后续问题）**：下发 1 真人 + 5 机器人（`11041/11012/11014/11006/11009`），每人 109 条 builds、3~5 个英雄。

## F. GM

### F1 GM 指令全部回「未实现」
- **根因**：`runGM` 只认 `addItem`/`adventureSkipLevel`/`gmStr` 三个 cmd，`AddRewards` 落到 else。
- **修法**：重写 `runGM`，覆盖面板 52 条里的主要项（见 `03-协议与数据` 的 GM 全表）。

### F2 `getPackageAndOperId` 让客户端崩
- **根因**：`GMModule._send` 里 `JSON.parse(t.retExtra)`，必须回合法 JSON `{"id1":..,"id2":..}`。
- **修法**：`runGM` 里对 `cmd === "getPackageAndOperId"` 直接回 `{"id1":0,"id2":0}`。

### F3 GM 生效但界面不刷新
- **根因**：只回了 `clientReward`，客户端只结算不刷新 `PlayerModule`。
- **修法**：`5/174` 回包后服务端**主动推** `13/5 PlayerInfoP` + `23/9 HeroInfoP` + `11/12 AdventureInfoP`。
- **注意**：`13/5` 必须带**完整** `info`（含 `moduleBaseList`），否则 `_updateBuildSkinRed` 抛 `moduleBaseList.forBreak`。

### F4 GM 面板物品 ID 不知道
- **现状**：`sy_api/data/items.json`（1732 条）已有，但没做成界面。
- **下一步**：做 `sy_api/gm.php` 搜索 + 发放，或把 items 灌进 GM 面板的下拉框。

## G. 存档 / 日志 / 维护

### G1 存档「没有存档」
- **机制**：Deno 内存存档 + 800ms 合并写盘到 `sy_api/state/player.php`（`internal.php` 用 tmp + rename 原子写）。
- **排查点**：`internal.php` 返回 `{ok:1}`? `state/` 可写? 多端同 playerId 会不会互相覆盖?
- **注意**：Deno isolate 被回收时内存丢失，但每次改动都会 `queueSave`，正常不会丢。

### G2 日志上报拿不到堆栈
- **根因**：动态 `<script>` 没有 `crossOrigin`，跨域脚本报 `Script error. 0 0`。
- **修法**：`s.crossOrigin = "anonymous"` + `window.onerror` 里把 `e.filename/lineno/colno` 一起上报。

### G3 维护开通了但还能进
- **排查顺序**：PHP 是否新包（`maint.php` 存在）→ `state/` 可写 → Deno 是否读到 `maintenance:true`（10 秒缓存）→ 客户端是不是走了缓存页面。

## H. 工具库（必看）

### H1 `getNewAdvLessTime() < 5` 就弹「体力不足」
`AdventureMainCom._onBtnChalenge` 先判断 `_costs[2]=5` 点体力；`AdventureInfo.lessTimes` 要回 ≥ 5（本项目回 25）。**这条不满足，点「开始挑战」只会弹购买体力窗，看起来像「进不了对局」。**

### H2 主城「开始挑战」按钮 `active=false`
按钮开关是 `AdventureInfo.isGetFirstCustoms`，必须回 `true`，否则 `btn_adv_challenge` 节点不存在（自动化脚本会报 `notfound`）。

### H3 Cocos 横屏坐标换算
`cc.view._isRotated = true` 时，`convertToLocationInView` 返回 `(canvas.width - x, y)`，再经 `_convertPointWithScale` 除以 `_scaleX/_scaleY`。
自动化点击必须走这套换算，否则点不中。

### H4 自动化点按钮不要用 `dispatchEvent(0)` 直接触发 `GameButton`
`_checkTouchIn` 依赖真实 TouchEvent 坐标。用 BFS 找到带 `_eventStore` 的组件后直接 `dispatchEvent(0)` 才稳。

### H5 Chrome 残留进程导致 `ECONNREFUSED`
`pkill -f "chrome-linux64/chrome"` + 每次 `--user-data-dir=chromeprof_xxx` 唯一化。

### H6 `cc.Label` 在 Cocos 2.x 里叫 `GameLabel`
遍历文本用 `_components` + `__classname__`，不要 `instanceof cc.Label`。

## I. 一句话总结（给未来的自己）

> 这个项目 90% 的坑集中在三处：**<base> 与资源路径**、**protobuf 的 Map/类型编码**、**回包少字段导致客户端 undefined**。
> 任何「界面没反应」先看控制台有没有 `TypeError: Cannot read properties of null/undefined`，八成是回包缺字段，而不是服务端没收到。
