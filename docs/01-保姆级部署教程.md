# 01 · 保姆级部署教程（手机也能照做）

> 目标：从**零**开始，把「PHP 后端（zx.lytnb.top）+ 免费云 WebSocket（Deno Deploy）」重新跑起来。
> 全程只需要：一个 GitHub 账号、一个 Deno Deploy 账号、一个**支持 PHP 的虚拟主机**（本项目用的是 `zx.lytnb.top`）、一部手机/浏览器。

---

## 0. 先搞清楚为什么要分成两半

虚拟主机**只能跑 PHP**（请求进来 → 执行 → 返回 → 结束），没有常驻进程。
游戏要用 **WebSocket 长连接**，必须有常驻进程 → 放到免费的 Deno Deploy。

```
PHP 主机：只负责
  · /game.html            发页面（含 <base>、SDK 桩、日志 hook）
  · /sy_api/game_api.php  登录，返回服务器地址（指向 Deno）
  · /sy_api/get_versionInfoApi.php  版本信息 / 开关（OpenGM、CloseGuide…）
  · /sy_api/data.php      协议表、指令表、道具表、真实回包
  · /sy_api/files.php     remoteConfig/*.bin（官方 CDN 上缺这两个文件）
  · /sy_api/internal.php  存档读写（token 保护）
  · /sy_api/log.php       日志上报 / 汇总 / 查询
  · /sy_api/maint.php     维护状态
  · /sy_api/admin.php     维护后台（一键开/关）

Deno：负责
  · /ws                 游戏服（登录、主城、抽卡、进房…）
  · /ws?role=battle     战斗服（Auth、StartGameP、QuitRoomR…）
  · /health             健康检查（能看到 tables/online/maintenance）
```

## 1. 部署 PHP 后端（10 分钟）

### 1.1 上传

1. 拿到 `release/妖怪金手指_PHP后端_v1.0.12.zip`。
2. 用主机的「文件管理 / FTP」把它上传到**网站根目录**（就是 `zx.lytnb.top/` 对应的目录，和 `index.php` 同级）。
3. 解压。解压后根目录应该长这样：

```
/
├── index.php          ← 入口（维护时输出 503 维护页）
├── index.html         ← 入口守卫（先问 maint.php，维护中不跳转）
├── game.html          ← 真正的游戏页
├── proxy.php
├── .htaccess
├── h5SB_dalan.js
├── remoteConfig/
│   ├── config.hunfu147127.bin
│   └── preload_config.hunfu147127.bin
└── sy_api/
    ├── _common.php  _config.php
    ├── admin.php  maint.php
    ├── game_api.php  get_versionInfoApi.php
    ├── data.php  files.php  internal.php  log.php
    ├── data/       protocol.json / cmds.json / items.json / replay.json
    └── state/      （必须可写，存档和维维护状态都写这里）
```

> ⚠️ `.htaccess` 是隐藏文件，手机文件管理器默认不显示，确认它上传成功（否则 `index.php` 不会生效、入口会直接暴露 `index.html`）。

### 1.2 改配置

打开 `sy_api/_config.php`，只需要改这几项：

```php
'ws_host' => 'ygjsz-ws.19543687553-ai.deno.net', // ← 你的 Deno 域名，不要带 https://
'ws_port' => '443',
'token'   => 'CHANGE_ME_请替换成自己的token',             // ← 换成一串别人猜不到的
'cdn_host'=> 'menggui-cdnres.bhsg.lintey.com/huawei/web-mobile', // 官方 CDN，一般不动
```

### 1.3 给目录写权限

`sy_api/state/` 必须可写（Linux 主机设 755 或 777）。
验证方法：访问一次后台，页面会提示「state 目录可写」。

### 1.4 验证

| 请求 | 期望 |
|---|---|
| `https://你的域名/sy_api/maint.php` | `{"ok":1,"on":0,...}` |
| `https://你的域名/index.html` | 秒跳到 `game.html`（地址栏变成 game.html） |
| `https://你的域名/sy_api/admin.php?token=你的token` | 出现维护后台页面 |
| `https://你的域名/sy_api/data.php?f=protocol` | 1MB 左右 JSON |

## 2. 部署 Deno WebSocket（15 分钟）

### 2.1 准备仓库

1. GitHub 新建（或使用已有的）仓库，例如 `ygjsz-ws`。
2. 把 `src/deno-ws/server.mjs` 上传到**仓库根目录**，文件名保持 `server.mjs`。
3. （可选）把 `docs/`、`tools/` 也传上去，方便以后改。

### 2.2 在 Deno Deploy 建应用

1. 打开 <https://dash.deno.com/>，用 GitHub 登录。
2. **New Project** → 选 `Deploy from GitHub`（或 Playground）。
3. 选刚才的仓库，分支 `main`。
4. **Runtime Configuration**：
   - 模式选 **Dynamic App**（不是 Static）
   - Entrypoint 填 **`server.mjs`**
5. 环境变量（Environment Variables）：

| 名字 | 值 |
|---|---|
| `PHP_BASE` | `https://你的域名/sy_api` |
| `TOKEN` | 和 `_config.php` 里的 token **完全一样** |
| `PLAYER_ID` | 你的 playerId（默认 67820771，可省） |
| `VERBOSE` | `1`（想看日志）或 `0`（省额度） |

6. 部署完成后会得到一个域名，例如 `ygjsz-ws.19543687553-ai.deno.net`。
7. **把这个域名回填到 PHP 的 `_config.php` → `ws_host`**（改完 PHP 那边立即生效，不用重启）。

### 2.3 验证

```bash
curl https://你的deno域名/health
# → {"ok":true,"tables":1614,"online":1,"maintenance":false,"msg":""}
```

`tables` 为 0 说明 PHP 那边的 `data.php` 取不到 → 检查 `PHP_BASE` 和 token。

### 2.4 以后怎么更新（关键）

Deno Deploy 绑定了 GitHub 仓库：**push 就自动重新部署**，20~30 秒生效。

```bash
# 详见 docs/06-仓库与SSH推送.md
git add server.mjs
git -c user.name="ygjsz" -c user.email="ygjsz@local" commit -m "fix: xxx"
GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=no -p 443" git push origin main
```

## 3. 进游戏（客户端）

### 3.1 直接浏览器玩

打开：

```
https://你的域名/?game_id=191&channel_id=282&game_channel_id=7158&add_desktop=1&direction=2
```

或直接用官方入口（服务地址由我们拦截/替换）：

```
https://zeus.aidalan.com/v1/H5Game?game_id=191&channel_id=282&game_channel_id=7158&add_desktop=1&direction=2
```

> 注意：官方入口会跳到 `spirit.wbdd2018.com/h5sdk/index.html`，游戏本体在**跨域 iframe** 里。
> 若用自建入口，游戏页已经内置 `localConfig.HttpSerever = location.host + "/sy_api/game_api.php"`，不用额外拦截。

### 3.2 用壳 APK 玩（可选）

`apk/` 里有三个壳：

| 文件 | 用途 |
|---|---|
| `妖怪金手指_Mod版_v1.0.0.apk` | 内嵌 Mod 菜单（改钻石/金币/等级），走官方链接 |
| `妖怪金手指_抓包版_v2.apk` | 抓包壳：拦截 HTML 响应并注入 hook，把 XHR/WS 存成 JSON |
| `妖怪金手指_客户端.apk` | 早期版本，仅作参考 |

> 壳 APK 都只有十几 KB，因为它只是个 WebView 外壳 + 注入脚本，游戏资源全在线上。

## 4. 维护后台（一键开/关）

地址：

```
https://你的域名/sy_api/admin.php?token=你的token
```

- 输入公告（例如「服务器升级，10 分钟后回来」）、可选预计恢复时间
- 点「开启维护」→ 立即生效：

| 层级 | 表现 |
|---|---|
| 入口页 `index.php` | 返回 **503** + 维护页（带 30 秒自动刷新） |
| 入口守卫 `index.html` | 不跳转 `game.html`，只显示公告 |
| 所有 PHP 接口 | `yg_maint_guard()` 直接返回 `{"code":0,"msg":"...","maintenance":1}` |
| Deno WS | 握手直接 **503**（`maintStatus()` 读 `maint.php`，10 秒缓存） |

- 点「关闭维护」→ 立刻恢复（Deno 最多延迟 10 秒）。

> 维护状态存在 `sy_api/state/maintenance.php`，首行是 `<?php exit; ?>`，直接访问 URL 只会得到空白。

## 5. 更新流程（以后每次改代码）

```
改代码
 ├─ 改的是 server.mjs → push 到 GitHub → 等 30 秒 → curl /health 验证
 └─ 改的是 PHP       → 重新打包 zip → 用户上传解压 → curl maint.php 验证
```

打包命令（在本地/沙箱）：

```bash
cd /workspace
V=v1.0.13
zip -r "妖怪金手指_PHP后端_$V.zip" php-backend/web php-backend/sy_api \
  -x 'php-backend/sy_api/state/*'
```

> 打包时**必须剔除** `sy_api/state/*`（里面是真实存档和维护状态），只保留空目录。

## 6. 故障排查速查表

| 现象 | 最可能原因 | 怎么办 |
|---|---|---|
| 打开一片**黑屏** | 静态资源 404 | 检查 `game.html` 第一行 `<base href="https://menggui-cdnres.bhsg.lintey.com/huawei/web-mobile/">` |
| 卡在**进度条** | `remoteConfig/*.bin` 取不到 | 访问 `/sy_api/files.php?f=remoteConfig/config.hunfu147127.bin` 看是否返回二进制 |
| 控制台 `_h5_platform is not defined` | SDK 脚本 404 | `game.html` 里必须用**内联 SDK 桩**，不要再引 `/h5SB_dalan.js` |
| 地址变成 `https://https//...` | 协议拼了两次 | 服务端只返回 `host`，客户端用 `location.host` |
| 登录转圈 | Deno 没起来 / `PHP_BASE` 错 | `curl /health`，看 `tables` 是否 > 0 |
| 进主城后**功能全点不动** | 旧版兜底脚本把弹窗都 `active=false` | 兜底脚本只允许隐藏 `hangupoffline`（见 `02-踩坑`） |
| 进战场**没怪物** | 见 `04-当前进度与已知问题.md` P0 | 未解决，需要按交接说明第 1 步录制 |
| 打完一关**卡住/没结算** | `82/4` 没回 `uuid` 或 `err != 0` | 回包必须是 `{err:0, result:1, uuid:"..."}` |
| 维护开了还能进 | PHP 是旧包 / `state/` 不可写 | 访问 `maint.php` 看 `on` 是否变 1 |

## 7. 免费额度提醒

Deno Deploy 免费额度有限（本项目最后就是因为额度耗尽而封存，`/health` 直接返回 `503 USAGE_EXCEEDED`）。
省额度的做法：

- `VERBOSE=0`（关日志）
- 让 Deno 只做 WS，不代理静态资源（本项目已经这样）
- 长时间没人玩时开维护模式（Deno 依然会休眠，但至少不会被 WS 长连接占满）
- 想彻底省钱：把 `server.mjs` 换到任何一个能跑常驻 Node/Deno 的地方（VPS、Railway、Cloudflare Workers + Durable Objects），代码逻辑不用改。
