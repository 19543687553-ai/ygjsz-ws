## 1. 封包

### C2S（客户端 → 服务端）
```
偏移 0  uint16 BE  total      // 整包长度
偏移 2  uint8      module
偏移 3  uint16 BE  cmd
偏移 5  uint8      ssid
偏移 6  body       // protobuf
```

### S2C（服务端 → 客户端）
```
偏移 0  uint16 BE  total      // 整包长度
偏移 2  uint8      ssid
偏移 3  uint8      id         // 回包序号
偏移 4  uint8      count
偏移 5  uint8      module
偏移 6  uint16 BE  cmd
偏移 8  uint8      compress   // 0 = 不压缩
偏移 9  body
```

> 头部总长 **9 字节**。实测样例：`4dfb0001015a000c00` → total `0x4dfb`、ssid 0、id 1、count 1、module `0x5a`=90、cmd `0x000c`=12（StartGameP）、compress 0。

### SSID 约定
- 客户端请求带 `ssid`（事务号），服务端回包必须**原样带回**，客户端靠它匹配回调。
- 本项目 `reply()` 里统一用收到的 `ssid`；主动推送（`P` 结尾的消息）用 `ssid = 0`。

## 2. 极简 protobuf 规则

- 只支持 `varint(0) / double(1) / string(2)` 三种 wire type。
- 字段表（`protocol.json`）里的 `rule` 是 `Repeated / Optional`，`type` 是 `int32/uint32/int64/uint64/bool/double/string/object`。
- **`object`** 类型表示嵌套 message，`name` 指向 `SCHEMA` 里的另一条。
- **`Map`** 字段只写值类型（`"attr": {"rule":"Repeated","type":"uint32"}`），key 类型没有声明 → 编解码只能按 wire type 判断（0=varint，2=string）。
- `int64/uint64` 编解码用 BigInt；**不要 `JSON.stringify` 原始对象**。

### 容易踩的编码坑
```js
// ❌ 错：丢了 f.type，Map 的 value 会被当 string 编
const md = (mapDefs || {})[name + "." + f.name];
encodeField(w, f, v, md || {});

// ✅ 对
const md = Object.assign({}, f, (mapDefs || {})[name + "." + f.name] || {});
encodeField(w, f, v, md);
```
