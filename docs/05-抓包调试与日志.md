## 1. 抓包壳原理（`apk/妖怪金手指_抓包版_v2.apk`）

```
WebView 加载任意 URL
  └─ shouldInterceptRequest(请求)
       ├─ 只处理 text/html 响应
       ├─ 把 HTML 读成字符串
       ├─ 在 <head> 后插入 inject.js
       └─ 返回新的 WebResourceResponse

inject.js（页面最早执行）
  ├─ hook XMLHttpRequest.open/send  → 记 http 请求/响应
  ├─ hook fetch                      → 同上
  ├─ hook WebSocket
  │    ├─ onopen  → 记 ws_open
  │    ├─ onmessage：ArrayBuffer → base64；string 原样
  │    └─ onclose → 记 ws_close
  └─ 通过 @JavascriptInterface 调原生 save(JSON)

原生侧：把 frames 累积成
  { v, savedAt, frames:[{ url, recs:[ {k, ...}, ... ] }] }
  落盘成 ygcap-<ts>.json
```

**关键点**：游戏在**跨域 iframe** 里，所以必须「每个 HTML 文档都注入」，不能只拦主框架。

### 抓包 JSON 读取
```js
const cap = require("./data/capture/capture-main.json");
for (const f of cap.frames) {
  for (const r of f.recs) {
    if (r.k === "ws_msg") {
      const buf = Buffer.from(r.b, "base64");   // 二进制帧
      const module = buf[5], cmd = buf.readUInt16BE(6), body = buf.subarray(9);
    }
  }
}
```

## 2. 日志上报服务器

### 2.1 客户端 → 服务端
`game.html` 里注入了 hook：
```js
window.onerror = (msg, file, line, col, err) => report("error", {...});
// console.log/warn/error 全部 hook 一份
// 用 navigator.sendBeacon 或 fetch(POST) 发到 /sy_api/log.php
```
> 动态 `<script>` 必须 `crossOrigin="anonymous"`，否则只能拿到 `Script error. 0 0`。

### 2.2 服务端接口（`sy_api/log.php`）
```
GET  ?token=xxx&mode=summary        → 各条消息计数排行（先看这个）
GET  ?token=xxx&mode=miss           → 未处理指令统计
GET  ?token=xxx&mode=json&tail=400  → 最后 400 条原始日志（含堆栈）
GET  ?token=xxx&mode=json&q=关键字   → 搜索
GET  ?token=xxx&mode=json&day=2026-10-24
```
常用姿势：
```bash
T=你的token
curl "https://zx.lytnb.top/sy_api/log.php?token=$T&mode=summary" | head -c 3000
curl "https://zx.lytnb.top/sy_api/log.php?token=$T&mode=json&tail=400" -o /tmp/yglog.json
node -e 'const j=require("/tmp/yglog.json");j.rows.filter(r=>/Error|失败|找不到/.test(r.m)).forEach(r=>console.log(r.m))'
```

### 2.3 Deno 侧
```
GET /health          → {ok, tables, online, maintenance, msg}
GET /logs?token=xxx  → {miss:{...}, online:n}   // 未实现指令统计
```
> 客户端点了某个功能、服务端没接住，就会出现在 `miss` 里 —— **这是找「哪个玩法打不开」的最快入口**。

## 3. 浏览器调试配方（Playwright / CDP）

历史脚本已打包在 `tools/e2e.mjs`、`tools/probe.js`，套路如下。

### 3.1 启动
```js
const { chromium } = require("playwright");
const b = await chromium.launch({
  executablePath: process.env.HOME + "/.cache/ms-playwright/chromium-*/chrome-linux/chrome",
  args: ["--no-sandbox", "--user-data-dir=/tmp/chromeprof_" + Date.now()],
});
```
> 残留进程会导致 `ECONNREFUSED`：先 `pkill -f "chrome-linux64/chrome"`。

### 3.2 注入探针（必须在页面脚本执行前）
```js
await page.addInitScript(() => {
  window.__yg = { logs: [] };
  const oldLog = console.log;
  console.log = (...a) => { window.__yg.logs.push(a.map(String).join(" ").slice(0, 500)); oldLog(...a); };
});
```
> 用 CDP 的 `Page.addScriptToEvaluateOnNewDocument` 时，**必须在 `ws.onopen` 之后**发，否则报 `Sent before connected`。

### 3.3 点 Cocos 按钮的两种方法
```js
// 方法 A：按键名找节点（推荐）
//   节点树：node 名 btn_adv_challenge / btn_challenege（注意拼写）
// 方法 B：BFS 找带 _eventStore 的组件，直接 dispatchEvent(0)
function tap(nodeName) { /* BFS -> comp -> comp.dispatchEvent(0) */ }
```
> **不要**用 `dispatchEvent(0)` 直接触发 `GameButton`：`_checkTouchIn` 依赖真实 TouchEvent。

### 3.4 坐标换算（横屏）
```js
cc.view._isRotated === true;
// convertToLocationInView: x = canvas.width - x, y = y
// 再 _convertPointWithScale: x /= _scaleX, y /= _scaleY
```
自动化点击必须走这套，否则点不中。

### 3.5 采样战场状态
```js
await page.evaluate(() => {
  const B = /* 从全局拿 BattleModule，或从 cc.director.getScene() 找组件 */;
  const vo = B._battleQueue[0];
  return { battleType: vo.battleType, level: vo.level };
});
```
找不到模块时的通用办法：`cc.director.getScene()` 递归，按 `__classname__` 找组件（`cc.Label` 在 2.x 里是 `GameLabel`）。

## 4. 离线验证 `server.mjs`（没有 Deno 二进制时）

`tools/test_sgp.mjs` 的做法：

```js
// 1) 打桩 Deno 环境
globalThis.Deno = { env: { get: (k) => ({ PHP_BASE: "...", TOKEN: "..." })[k] } };
// 2) mock fetch 读本地 data/*.json
globalThis.fetch = async (url) => ({ ok: true, json: async () => require(...) });
// 3) 把 server.mjs 截断到 Deno.serve 之前，追加 export，动态 import
const src = fs.readFileSync("server.mjs", "utf8").split("// ---------------- 连接 ----------------")[0];
fs.writeFileSync("/tmp/mod.mjs", src + "\nexport { encode, decode, runGM, battleStartGameP, ... }");
const mod = await import("data:text/javascript;base64," + Buffer.from(fs.readFileSync("/tmp/mod.mjs")).toString("base64"));
// 4) 断言
const buf = mod.encode("StartGameP_BuildRoom_S2C", obj);
const back = mod.decode("StartGameP_BuildRoom_S2C", buf);
```

> 注意：解码出的 int64 是 BigInt，打印时统一用
> `JSON.stringify(o, (k,v)=> typeof v==="bigint" ? String(v) : v)`。

## 5. 真连生产测试（`tools/prod.mjs`）

```bash
node tools/prod.mjs
```
流程：`/health` → 连 `wss://.../ws` → `2/1 LoginGame` → `82/6 UnfinishedRoom` → `82/1 EnterRoom` → 连 `wss://<addr>` → `90/1 Auth` → 等 `90/12 StartGameP` → 断言 6 人 / 109 builds / 版本号。
**不发 `82/4`**（避免改用户存档）。

> Node 的 `WebSocket` 必须设 `ws.binaryType = "arraybuffer"`，否则收到的是 Blob，解包失败。

## 7. 日志里常见字样 → 含义

| 日志 | 含义 |
|---|---|
| `[TDServer] 阵营N,第M帧,执行客户端操作类型 X` | 战场 AI 生成了操作（X=选择房间/升级/建造/召唤/出怪/躺下） |
| `[TDServer] delegate操作:阵营:N：第M帧,实际效果:出怪时机` | 波次触发点到了 |
| `[GameRoomSocket] 协议解析发生错误` | 服务端编码不对（长度/类型），**优先查 Map 编码** |
| `[HangupOfflineRewardView] 打开窗口` | 离线收益弹窗被自动打开（`getDt` 太旧） |
| `Script error. 0 0` | 跨域脚本异常，需要 `crossOrigin` 才能拿到堆栈 |
| `Cannot read properties of null (reading 'xxx')` | 服务端回包缺字段 |
| `战场配置找不到: xxx` | `level` 对应的 `BattleGroundLO` 不存在 |
| `房间服认证失败N` | `90/2 AuthR err != 0` |
| `已存在战斗类型为N的游戏房间` | 上一局 `roomState` 没退出（`exitRoom` 没走） |
